# JQIT Corporate — デザイン定義

更新日: 2026-11-12 / 実装確認基準: `3027f52` と現在のワークスペース。

現行サイトの見た目・配置・動きを再現するための定義。新しいページ・部品を作るときの参照先とする。このファイル自体は実行用設定ではない。実装変更時は対応するCSS/コンポーネントと本定義を一緒に更新する。末尾の追加候補は現行仕様と区別する。

## 1. デザインの軸

- 写真と文章を主役に、白・赤・薄赤・紙色・極薄グレーで構成する。
- 写真の大小、左右の配置、余白の量でリズムを作る。全項目を同じ大きさの箱にしない。
- 曲線は一角だけ大きく曲げる。背景は角の丸いルート線と、一角を曲げた薄赤の面に絞る。
- 動きは「初回の登場」「スクロール中の奥行き」「ページ遷移」「操作への反応」を別々に設計する。
- 本文・写真の枠は読める位置に収める。背景だけがその後も動き、写真は枠の内側で動く。
- 装飾のための01/02番号、写真の上に別の写真を載せる構図、黒い帯の反復、図形の機械的なローテーションを避ける。工程など順序のある番号は使用できる。

## 4. 曲線・余白・レイアウト

| トークン | 値 | 用途・向き |
|---|---|---|
| `--curve-base` | 2px | 大きく曲げない残りの角 |
| `--curve-section` | `clamp(64px,10vw,144px)` | 帯の右下 |
| `--curve-media` | `clamp(48px,9vw,120px)` | 写真の右上。反転構図のみ左上 |
| `--curve-card` | `clamp(24px,4vw,48px)` | カードの右上 |

写真の標準形は `0 R 0 0`、カードは `2px R 2px 2px`。例外は確定済みヒーローのコラージュ、切り取りを避ける図解・ロゴ・製品画面、本文中の画像等。

- 基本コンテナ: 最大1160px、左右24px。TOP事業エリアは1000px以上で最大1320px・左右48px。
- 下層のセクション縦余白は主に80〜100px。ページごとに内容量へ合わせる。
- TOP事業: 1段目は大きい写真、2段目は小さめの写真を右に置く。1000px未満で縦積み、2枚目は幅78%。
- TOPサービス: 1000px以上は1段目全幅、2段目幅86%で右寄せ、写真と説明の左右を入れ替える。小画面は縦積み、2段目幅92%。
- 行動指針: PCは左に導入（top128pxでsticky）、右に6つの文章。偶数項目を少し右へ。719px以下は1列でstickyを解除する。
- 企業理念: 英語ラベル＋定義の行。DX指標は指標名と目標の定義リスト、開発工程は縦タイムライン。
- コラム一覧: 日付・タグ200px＋記事本文、間48px。719px以下は縦積み。
- 異なる色の帯は次の帯を角の下へ潜らせ、曲線の外に白い欠けを作らない。

境界幅は共通1個に統一されていない。719/720pxは本文・共通スマホ表示、899/900pxは見出し帯等、999/1000pxはTOPの構図、1279/1280pxはヒーロー画像配置に使う。個別部品には600/760/1024/1200px等もある。

## 5. 写真・アイコン・部品

- 写真は `object-cover` を基本に、人物や被写体に合わせて `object-position` を指定。製品画面・図解は切らずに読める状態を優先する。
- 下層見出し帯は左にタイトル・リード、右に写真。写真比率4:3、最大高400px、899px以下は16:9で縦積み。
- 見出し帯写真は帯から `clamp(40px,5vw,72px)` はみ出す。帯の下にはその量＋24pxの間隔を確保する。
- 見出し帯の写真・文・トリミング位置は `lib/page-header-content.ts` に集約。同ページ冒頭の写真と同じ素材を繰り返さない。法務ページは写真なし。
- `public/page-header/*.webp` の生成写真に写る人物を実在社員の記録写真として扱わない。
- ボタンprimary: 赤地・白字、左右32px/上下15px、角2px。outline: inkの1px枠・上下14px、ホバーでink地/白字。arrow: 下線付きテキスト。
- ボタンの矢印はSVG、20×10、線幅1.4、丸い線端・接合。装飾アイコンは `aria-hidden`。ニュース等の公式ロゴを無断で流用しない。
- 相談導線: フッター直前の紙色帯・右下R・電話・行リンク。/contact、/introduction、/design-lab、/demo-gallery、/dispatch-disclosureとその子パスには表示しない。

## 6. 動きの共通値

| 用途 | 値 |
|---|---|
| 基本イージング | `cubic-bezier(.16,.84,.44,1)` |
| 短い動きのトークン | `--motion-short:240ms`（全ての動きがこの値を使うわけではない） |
| 通常のスクロール登場 | opacity0→1、Y22px→0、700ms |
| 下層見出しの登場 | opacity0→1、Y8px→0、550ms |
| 下層見出し写真の登場 | 同じ変化、700ms、遅延120ms |
| 通常ボタン | 300ms ease-out、矢印X+6px、押下Y+1px |

FadeInは初めから画面内なら表示したまま。下にある要素だけを1回表示する。IntersectionObserverのthreshold `.1`、rootMargin下端 `-8%`。安全確認は2600msごとで、画面外の要素を一律に表示するタイマーではない。

## 7. TOPの確定した登場演出

順序: **写真は最初から表示 → JQIT Corporate Siteを左からタイプ → 主コピーを上の行からゆっくりタイプ → 補足説明 → ヘッダー・ボタン・画像操作部**。

| 段階 | 定義 |
|---|---|
| 肩ラベル開始 | 演出開始から120ms |
| 肩ラベル | 1文字45ms間隔 / 各文字140msフェード |
| 主コピー開始 | 肩ラベルの終わり＋250ms |
| 主コピー | 1文字150ms間隔 / 各文字200msフェード / 行間400ms |
| 説明文 | コピーのカーソル終端＋180ms、550msフェード |
| ヘッダー | 同終端＋900ms、650msフェード |
| CTA・画像操作部 | ヘッダー開始＋100ms、650msフェード |
| 全体終了 | ヘッダー開始＋750ms |

現行コピーでは肩ラベル終了980ms、ヘッダー開始5630ms、全体6380ms。文字数を変えると総時間も変わる。文字は位置を跳ねさせず透明度で表示する。文字用イージング `.2,.65,.35,1`、要素フェード `.2,.75,.25,1`。

初期画像は停止。共通カルーセルは通常5000ms周期・opacity1350msだが、このTOPラッパーでは自動再生を停止し画像のドリフトとクロスフェードも上書き停止する。通常カルーセルの仕様と確定TOPを混同しない。

アンカー付き表示・復元スクロール・ユーザースクロール（32px超）は操作を優先し演出を完了する。フォント待機上限1800ms、未初期化時のCSS表示復帰2200ms。reduced-motion/JS無効時も文字・操作部を隠したままにしない。

## 8. TOPのスクロール奥行き

レイヤー順: **背景の線/面 → 本文と写真の枠 → 写真内部 → 手前のラベル**。写真・カードの枠は読み取り位置（上端が画面高の60%以下）に入ったら本来の配置へ着地し、ずれ続けない。背景と写真内部はその後も移動する。

| 対象 | 縦速度係数 | 横速度係数 | 上限等 |
|---|---:|---:|---|
| Aboutのルート線 | .10 | 0 | 縦80px / 横80px |
| 事業01写真背面のルート線 | .12 | -.05 | 同上 |
| 事業02写真背面の薄赤面 | -.08 | .04 | 同上 |
| Cultureのルート線 | .08 | .04 | 同上 |
| 背景英字見出し | -.14 | 0 | 登場移動36px |
| 事業の写真枠 | -.18 | 0 | 登場移動96px、スマホ16px |
| IT写真内部 / AI写真内部 | -.075 / .06 | 0 | `min(32px×強度,写真高×.045)` |
| 導入支援の人物写真内部 | -.05 | 0 | 同上 |
| サービスカード1 / 2 | -.10 / -.15 | 0 | 登場移動64px |
| カルチャーカード | `-.06 - index×.035` | 0 | 登場移動56px |
| 写真上ラベル | -.025 | 0 | 登場移動12px |

背景・写真内部の距離基準は `画面高/2 − 対象上端 − 対象高/2`。背景は係数×距離を上限内に制限する。見出し・枠・カードの実移動は上表係数ではなく、画面への入り具合に対するsmoothstepと登場移動上限で決まる。719px以下の強度は.65、その他1。背景の上下はセクション内に収め、左右は画面端へ逃がす。

写真内部は1.12倍に拡大し、枠から空白を出さない。reduced-motionでもこの拡大・トリミングは維持し移動を止める。模様は写真・情報ブロックの寸法を基準に配置し、ウィンドウ幅の割合だけで適当に散らさない。サービス背景には模様を足さない。719px以下では事業の線と面を非表示、Cultureの線はopacity.5。

**現状のTOP背景には下層と同じスクロール減衰は実装されていない。**

## 9. 下層のスクロール奥行き・減衰

`PageMotion`が制御。明示したmain直下の `section[data-depth-scene]` を使う。指定がなければ、見出し帯・相談導線以外の最初のセクション1個を対象とする。形は `route` / `plane`。複数対象は右→左の配置になり、形自体を順番で切り替えない。

- route: 幅 `clamp(480px,54vw,820px)`、比率560:460。画面端へ一部を逃がす。719px以下は幅460px、端から340px外へ、濃度は計算値×.6。
- plane: 大きさ520px、画面内の幅 `max(40px,(100vw−1208px)/2)`。内側に見える角を曲げる。本文の外側へ置き、719px以下では表示しない。横移動なし。
- 現行の明示箇所: Aboutメッセージ=route、Vision理念=route/行動指針=plane、IT/AIイントロ=route/強み・NOVA=plane。

以下でH=画面高、t=対象の上端、h=対象高、`clamp(x,a,b)`はxをa〜bへ制限する。

```text
progress = clamp((H/2 - t) / (H + h/2), -1, 1)
背景Y = progress × 100px
背景X = routeならprogress × 24px、planeなら0
fade = clamp((H×.25 - t) / (H + h×.3), 0, 1)
背景opacity = 1 - fade×.9
```

左のrouteは左右反転しているため、見た目の横移動方向も反転する。逆スクロールで位置・濃度も戻る。TOPと同じ時間制御のループではない。

写真は明示した `[data-depth-photo]` だけが対象。枠は固定し、中身を1.09倍に拡大。画面内の写真順で上/下を交互にする（見出し帯の写真も順番に含まれる）。

```text
photoProgress = clamp((H/2 - t - h/2) / (H×.7), -1, 1)
写真Y = photoProgress × min(24px,h×.04) × (偶数indexなら-1、奇数なら+1)
```

reduced-motionでは背景移動0・減衰なし（opacity1、スマホrouteはその.6倍）、写真transformなし。JS無効時は下層の動的背景を追加せず、本文と写真は通常表示。スクロール処理はpassiveイベント＋requestAnimationFrameにまとめる。

## 10. ページ遷移と小さな反応

- 遷移の幕: 薄赤、ヘッダー73px下から、右下R、z-index45、操作を遮らない。940msで上へ-104%。最初の30%は静止。1000msで撤去。
- 幕がある遷移の見出し文字開始は520ms後、写真640ms後。遷移属性を1500ms後に解除。
- 初回・戻る/進む・reduced-motionでは幕なし。遷移後は本文へフォーカス。幕が出ている間は自動の先頭復帰をsmoothにしない。
- マウス＋通常モーション: リンク内写真（object-contain除外）はhoverでscale1.04、800ms。曲げたカード角は1.8倍、500ms。フッターの下線は左から伸びる、350ms。
- 共通行部品: ホバーで薄い背景、左の2px赤線が伸びる（320ms）、ラベルX+3px（320ms）。これは既存の個別部品ルール。
- 相談行リンク: 色450ms、矢印X `clamp(8px,1.2vw,20px)`・550ms。

## 11. ページ固有の見せ場

CSS `animation-timeline:view()` 対応＋通常モーションの場合のみ。時間のmsではなくスクロール範囲に対応する。非対応環境では静止表示。

## 13. 追加候補 — 線の連続性を使った演出（未実装）

参考: https://www.landbridge.co.jp/ （2026-11-12に実画面・SVGを確認）。参考サイトの図形そのものを転用せず、JQITの線・色・構図で設計する。

- **TOP→次のセクションを横切る波線**: スクロール量に追従して大きな線が横切り、TOPと本文のつながりを作る。登場演出と同時に自動再生せず、ユーザーが読み進める動きに合わせる。主コピー・メイン写真を塞がない。
- **背景ルート上を滑る小さな丸**: 同じ線の上を小さな点が進む。既存のルート線に動きの方向を与え、意味のない図形追加を避ける。参考サイトの点はパスに沿った時間ループ（約8〜10.8秒）だが、JQIT側の速度・点数・スクロール連動の有無は未確定。
- 波線は主にセクション間の接続、小さな丸は背景の継続的な動きとして役割を分ける。発光・多色・大量の粒子は足さず、赤/薄赤/灰の既存パレットに収める。
- 実装候補はSVGのパス＋点の経路アニメーション。画像生成ではなく、線上の位置を正確に制御できる描画を使う。
- reduced-motion時の静止表示、スマホでの線の本数・丸の数の調整を含めてモックで判断する。既存の曲線ルールへの例外は、この候補を採用した時点で更新する。
